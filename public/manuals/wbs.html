WBS 메뉴얼

작업분류체계(WBS) 항목을 등록·조회·수정하고, 엑셀로 내려받거나 대량 업로드하며, 전체·Stage별 공정율 통계를 확인하는 절차를 안내합니다.

대상: 전체 사용자 / 관리자·운영자(데이터 관리)기준 화면: WBS작성일: 2026-08-29 · 최종 수정: 2026-08-30

1. 기능 개요

WBS는 프로젝트 작업분류체계를 계층 구조(상위 항목 → 하위 항목)로 관리하며, 원본 엑셀 서식의 47개 컬럼을 그대로 다룹니다.

계층 구조

Task 코드("1.1.1.2")로 표현되는 최대 4레벨 트리 구조이며, 상위 항목을 지정해 하위에 등록합니다.

역할별 진척

Track(업무그룹)마다 진척등록권한과 진도율을 따로 관리하며, 실적은 배정된 Track들의 평균으로 자동 계산됩니다.

사이드바 메뉴: 전체 목록 · WBS 항목 등록 · 통계 · 데이터 관리

2. 전체 목록·검색

경로: WBS → 전체 목록

엑셀 원본과 동일한 47개 컬럼(wbs_level, sort, Task, Task Description, 역할별 진척등록권한·진도율 등)을 표 형태로 보여줍니다.

① 검색 조건
다음 조건을 개별 또는 조합해 입력한 뒤 조회를 누릅니다. 초기화로 모든 조건을 지웁니다.

3. WBS 항목 등록

경로: WBS → WBS 항목 등록

한 화면에서 기본 정보, 역할별 진척등록권한·진도율, 산출물 검수 정보를 함께 입력하고 등록하기 한 번으로 저장합니다.

구분항목
기본 정보상위 항목, 상태, Track, 담당자, 시작일·종료일, 설정상태, 가중치, 항목명(필수), 내용
역할별 진척등록권한·진도율Track별 등록권한 체크와 진도율(%)
산출물 검수산출물템플릿, 파일위치, 검수자, 검수실행일, 공식 산출물 확정 여부, 이슈 및 사유
가중치를 비워두면 시작일~종료일 사이의 영업일수(공휴일 제외)로 자동 산정됩니다.

4. 상세 조회

항목 상세 화면은 기본 정보, 담당·일정, 진척 현황, 역할별 진척등록권한·진도율(전체 Track), 산출물 검수, 하위 항목을 그룹별 카드로 보여줍니다.

화면 하단의 이력 보기 버튼을 누르면 등록·수정·이동·보관 이력을 모달로 확인할 수 있습니다. 수정 버튼으로 수정 화면으로 이동합니다.

5. 항목 수정

경로: 상세 화면 → 수정

기본 정보 수정, 역할별 진척등록권한·진도율, 산출물 검수가 각각 독립된 패널로 나뉘어 있으며, 패널별로 따로 저장합니다.

동시 수정 보호
다른 화면에서 같은 항목이 먼저 저장되면 버전 충돌로 저장이 거부될 수 있습니다. 화면을 새로 열어 최신 내용을 확인한 뒤 다시 수정하십시오.

항목 보관

화면 하단 데이터 초기화가 아닌 보관 처리는 이 항목과 하위 항목 전체를 목록·조회에서 제외합니다(복구 가능한 보관 처리이며 삭제가 아닙니다).

6. 통계

경로: WBS → 통계

상단에 전체 목표(계획)·실적·진척율·지연율 4개 KPI를 보여주고, 하단에는 Stage(최상위 항목, Task 번호 순)별 Task 건수·계획·실적을 비교하는 막대 그래프와 동일한 수치의 표가 나옵니다. 표 맨 아래에는 전체 합계 행이 굵게 표시됩니다. 실적이 계획보다 낮은 Stage는 그래프에서 항목명이 붉게 표시(⚠)되고, 표에서는 지연 배지로 표시됩니다.

공정율 계산 기준

지표계산 방법
목표(계획, today 기준)오늘 날짜를 시작일~종료일 구간에 선형보간한 경과 비율입니다. 시작일 이전이면 0%, 종료일 이후면 100%, 구간 중이면 (경과일수+1)/(전체기간+1)로 계산합니다.
실적항목에 배정된 Track(업무그룹)별 진도율(0~100, 사용자가 입력)의 평균입니다. 배정된 Track이 하나도 없으면 0%입니다.
진척율실적 ÷ 목표입니다. 목표가 0%(시작 전)이면 0%로 표시합니다. 100% 미만이면 계획 대비 실적이 뒤처진 상태입니다.
지연율시작일·종료일이 모두 입력되어 목표를 계산할 수 있는 항목(leaf) 중 실적 < 목표인 항목의 비율입니다. 날짜가 비어 목표를 계산할 수 없는 항목은 분모·분자에서 모두 제외됩니다.
Stage 지연 판정Stage에 속한 leaf 항목을 가중평균한 계획·실적을 비교해 실적 < 계획이면 해당 Stage를 지연으로 표시합니다.
집계 대상 — 전체·Stage 통계 모두 하위 항목이 없는 최말단(leaf, 엑셀 "상세진도(진도관리대상)") 항목만 집계하며, 항목별 가중치(입력값, 없으면 시작일~종료일의 영업일수)를 기준으로 가중평균합니다. 상위 요약 항목은 집계에서 제외됩니다.

업무그룹별 통계

경로: WBS → 업무그룹별 통계

WBS 항목 자체의 R&R(지원)(모듈)이 아니라, 설정 → 사용자에서 담당자별로 지정한 업무그룹을 기준으로 공정율을 묶어서 봅니다. 각 leaf 항목의 담당자(R&R(실행))가 속한 업무그룹으로 항목을 모아 Stage 통계와 동일한 방식(막대 그래프 + 표)으로 Task 건수·계획·실적·진척율·지연율을 보여주며, 업무그룹이 지정되지 않은 담당자는 "미지정", 담당자 자체가 없는 항목은 "담당자 없음"으로 따로 집계됩니다. 업무그룹은 Groups 코드 순으로 정렬되고(코드가 없는 "미지정"·"담당자 없음"은 맨 뒤), 표 맨 아래에는 전체 합계 행이 굵게 표시됩니다.

업무그룹명을 클릭하면 그 업무그룹 담당자 전체의 Task 목록을, 지연율(전체 KPI 또는 그룹별 표)을 클릭하면 그중 지연된 Task만 모아 보는 화면(WBS → 업무그룹 Task 조회)으로 이동합니다. 이 화면 상단에는 담당자별 작업현황 막대 그래프와 표가 함께 나와, 조회 중인 Task들을 담당자별 Task 건수·완료 건수(실적 100%인 항목)·계획·실적·진척율로 다시 한 번 나눠 볼 수 있습니다.

주간 통계

경로: WBS → 주간 통계

업무그룹별로 총대상(건)·계획(건)·완료(건)·지연(건)·달성률(%)·진척률(%)을 보여주는 진행 현황 표입니다. 상단의 시작일·종료일(달력 입력)로 조회 기간을 자유롭게 바꿀 수 있으며, 기본값은 이번 주 월요일~금요일입니다. 계획(건)은 DueDate가 시작일~종료일 사이인 leaf 항목 수, 완료(건)은 그중 실적(담당자별 진도율)이 100%인 항목 수입니다. 달성률 = 완료/계획, 진척률 = 완료/총대상이며, 표 맨 아래에 전체 합계 행이 표시됩니다.

완료 시점을 별도로 기록하지 않아 "과거 시점 기준 완료 건수"는 정확히 재현할 수 없습니다 — 완료 여부는 항상 현재 실적 기준으로 판정되며, 시작일·종료일은 계획(건) 대상 기간만 바꿉니다.

7. 데이터 관리

경로: WBS → 데이터 관리 (관리자·운영자 전용 기능 포함)

엑셀 다운로드

현재 WBS 목록 전체를 원본 47개 컬럼 그대로 엑셀 파일로 내려받습니다.

엑셀 업로드

업로드는 전체 교체입니다 — 기존 WBS 데이터를 지우고 파일 내용으로 새로 만듭니다.

  1. 파일을 선택하고 검증(Dry-run)을 눌러 행별 오류·경고를 확인합니다. 결과 표에는 오류나 경고가 있는 행만 표시됩니다(정상 행은 표시하지 않고 상단에 건수만 요약합니다).
  2. 오류가 0건이면 반영 버튼이 활성화됩니다. 반영을 누르면 실제로 데이터가 교체됩니다.
담당자·Track은 이름으로 매칭됩니다
파일의 담당자·Track 이름이 현재 프로젝트에 등록된 사용자 이름, 그리고 설정 → 공통코드 → WBS 업무그룹에 등록된 Track 라벨과 정확히 일치해야 반영됩니다. 일치하지 않으면 오류는 아니지만 경고로 표시되고 해당 항목은 미지정으로 들어옵니다. 업로드 전에 프로젝트의 사용자·WBS 업무그룹이 파일과 맞는지 먼저 확인하십시오.

사용자ID로 담당자 확정 지정

엑셀 R&R(실행) 바로 뒤에 사용자ID 컬럼이 있습니다. 여기에 로그인 ID를 입력하면 이름 매칭보다 우선 적용되어 담당자가 확실하게 지정됩니다(비어 있으면 기존처럼 R&R(실행) 이름으로 매칭). 이 컬럼은 목록 화면에는 표시되지 않고 엑셀 업/다운로드에만 쓰입니다.

Stage가 "기획"인 행의 기본 담당자
Stage가 "기획"인 행에서 사용자ID·R&R(실행) 어느 쪽으로도 담당자를 확정하지 못하면(값이 비어 있거나, 못 찾거나, 이름이 겹쳐 여러 명이거나 등 사유 불문) 자동으로 담당자가 이승연(사용자ID: q93w36)으로 지정됩니다. 사용자ID나 이름으로 명확히 확정되면 그 값이 우선하며 기본값은 적용되지 않습니다.

동명이인 담당자 정리

경로: WBS → 데이터 관리 → 동명이인 정리로 이동

담당자 이름이 프로젝트 내 여러 사용자와 겹쳐 미지정으로 남은 WBS 항목을 모아 보여줍니다(Stage 기본값도 적용되지 않은 나머지 항목). 각 행에서 입력된 이름과 일치하는 후보(사용자ID·이름)를 드롭다운으로 선택하고 적용을 누르면 그 항목의 담당자가 즉시 확정됩니다.

WBS 업무그룹(Track)

설정 → 공통코드 → WBS 업무그룹에서 R&R(지원)(모듈)과 역할별 진척등록권한에 쓰이는 Track 목록을 관리합니다. 기본으로 PMO/IM·PM·업무공통·BO 기획·FO 기획·디자인·퍼블리싱·개발·시스템(TECH)·테스터 10개가 등록되어 있습니다. 이 목록은 다른 모듈(이슈·업무일지 등)의 업무그룹과 공유되지 않는 WBS 전용 코드이므로, 다른 화면의 업무그룹 설정을 바꿔도 영향받지 않고 WBS만 별도로 관리됩니다.

데이터 초기화

프로젝트의 모든 WBS 항목을 보관 처리합니다(복구 가능한 보관 처리이며, 완전 삭제가 아닙니다). 확인 대화상자를 거쳐야 실행됩니다.

9. 문제 해결

상황확인 및 조치
엑셀 업로드 시 날짜 오류(YYYY-MM-DD)가 뜸Excel에서 파일을 열었다 저장하면 날짜 셀 형식이 바뀌는 경우가 있습니다. 이 경우에도 자동으로 인식하도록 처리되어 있으니, 계속 오류가 나면 실제 셀 값을 확인해 알려주십시오.
업로드했는데 0건으로 처리됨파일에 다른 시트(예: 공휴일)가 함께 있으면 헤더가 "wbs_level"인 시트를 자동으로 찾아 읽습니다. 그래도 0건이면 헤더 행 구성을 확인하십시오.
담당자·Track이 미지정으로 들어옴정상 동작입니다 — 파일의 이름이 현재 프로젝트의 사용자 이름, 또는 설정 → 공통코드 → WBS 업무그룹에 등록된 Track 라벨과 다르면 발생합니다. 프로젝트 사용자·WBS 업무그룹 설정을 먼저 맞추십시오.
저장 시 충돌 메시지가 표시됨화면을 새로고침해 최신 버전을 확인한 후 다시 수정합니다.
데이터 관리 메뉴가 안 보이거나 초기화·업로드가 안 됨관리자·운영자 권한인지 확인합니다.
검색 결과가 없음Task·담당자 검색어를 초기화한 뒤 다시 조회합니다.
