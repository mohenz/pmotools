# 01. 기능 요구사항 정의서

표기: **[요청]** = 원 요구사항 그대로 / **[제안]** = 실무 운영을 위해 추가 제안하는 기능

---

## 1. 사용자 역할 (Role)

| 역할 | 설명 | 권한 |
|---|---|---|
| **관리자 (Admin)** | 프로젝트 전체 관리자 | 전체 CRUD, 사용자/그룹 관리, 엑셀 업/다운로드, 감사로그 조회 |
| **운영자 (Operator)** | 일정 등록·관리 실무자 | 일정 CRUD, 엑셀 업/다운로드 (사용자 관리 권한 제외) |
| **일반 사용자 (Member)** | 프로젝트 참여 인력 | 조회, 검색, 쪽지, 본인 정보/테마/비밀번호 관리 |

> **[제안]** 뷰어(Viewer, 열람 전용) 역할 추가 검토 — 외부 이해관계자에게 읽기 전용 링크 제공 시 필요 (Phase 2 이후 검토)

---

## 2. 일반 사용자 기능

### 2.1 회원가입/인증 **[요청]**
- 가입 항목: **사용자 ID, 사용자 이름, 비밀번호** 3개만으로 가입 (이메일 필수 아님)
- 비밀번호는 **단방향 암호화(bcrypt)** 저장 — 원문 복호화 불가
- **비밀번호 찾기(복구) 기능 없음** — 계정 잠금 시 관리자가 **강제 초기화(임시 비밀번호 발급)** 만 가능
- 로그인한 사용자는 **직접 비밀번호 변경** 가능 (기존 비밀번호 확인 후 변경) **[요청 #7]**

### 2.2 이메일 연동 (2단계 도입) **[요청]**
- 1단계: 이메일 없이 가입/사용 가능
- 2단계: "일정 이메일 수신" 기능 도입 시, **사용자 정보 화면에 이메일 입력란 추가** → 등록 시 일정 알림 메일 수신 가능
- **[제안]** 이메일 미등록 사용자는 알림 기능에서 자동 제외 처리, UI에 "이메일 미등록" 안내 배지 표시

### 2.3 캘린더 뷰 **[요청]**
- **년간 / 월간 / 주간 / 일간** 4종 뷰 제공, 뷰 간 전환 가능
- **[제안] 목록(Agenda) 뷰** 추가 — 모바일 기본 뷰로 채택 (첨부 디자인 참고: 모바일은 리스트형이 가독성 우수)
- **[제안]** 오늘로 이동(Today) 버튼, 이전/다음 네비게이션

### 2.4 주요 이벤트 모아보기 **[요청]**
- 우선순위 **"상"** 또는 **마일스톤(is_milestone)** 으로 지정된 일정만 모아보는 별도 화면/위젯
- **[제안]** 홈 대시보드에 "오늘 일정", "이번 주 주요 이벤트", "다가오는 프로젝트 마일스톤(오픈일 D-day 등)" 위젯 구성

### 2.5 일정 검색 **[요청]**
- 제목/메모/위치 키워드 검색
- **[제안]** 필터 검색 확장: 기간, 담당자, 업무그룹, 우선순위로 조합 검색

### 2.6 화면 테마 **[요청]**
- 밝게 / 어둡게 / 시스템 설정 3종, 사용자별 저장(로그인 유지 시 적용)

### 2.7 쪽지 기능 **[요청]**
- 사용자 검색 후 쪽지 발송
- 쪽지 내용은 **암호화 저장**, 열람 시 **비밀번호 입력**으로 조회 (발신 시 조회용 비밀번호 별도 설정)
- **[제안]** 미확인 쪽지 알림 배지, 발신함/수신함 구분, 쪽지 만료(자동 삭제) 옵션

### 2.8 알림 설정 **[제안]**
- 일정 알림 수신 여부, 리마인더 시점(예: 시작 10분/1시간/1일 전) 설정
- 이메일 미등록 시 인앱 알림만 제공

## 3. 관리자/운영자 기능

### 3.1 일정 중요도 관리 **[요청]**
- 우선순위: **상 / 중 / 하**, 각 등급별 색상 자동 매핑 (구체 색상값은 05-design-guide.md 참조)
- **[제안]** 업무그룹(카테고리)별 색상 지정 허용 → 우선순위 색상과 별도로 "카테고리 보기" 모드 지원 (첨부 디자인의 좌측 캘린더 목록/색상 구조 참고)

### 3.2 일정 반복 관리 **[요청]**
- 단기(단일) 일정 / 반복 일정 구분 관리
- 반복 규칙: 매일/매주/매월/매년 + 종료 조건(날짜 지정 또는 횟수 지정)
- **[제안]** 반복 일정 중 **특정 1회차만 수정/삭제(예외 처리)** 지원 — 실무에서 필수 (예: 매주 회의 중 1회만 시간 변경)

### 3.3 일정 등록 정보 **[요청]**
| 항목 | 필수 | 비고 |
|---|---|---|
| 일정(제목) | ✅ | |
| 일자 | ✅ | 시작일/종료일 |
| 반복 설정 | - | 없음/매일/매주/매월/매년 |
| 종일 여부 | ✅ | On 시 시간 입력 숨김 |
| 시간 | 조건부 | 종일 아닐 때 시작~종료 시간 |
| 우선순위 | ✅ | 상/중/하 |
| 위치 | - | 텍스트 |
| 메모 | - | 텍스트(장문) |
| **[제안]** 첨부파일 | - | 회의자료 등 (Supabase Storage) |
| **[제안]** 마일스톤 여부 | - | "주요 이벤트 모아보기" 노출 대상 플래그 |

### 3.4 캘린더 관리 (관리자/운영자) **[요청]**
- 일정 등록/수정/삭제, 사용자 관리
- 일정에 **업무그룹, 담당자 복수 지정** 가능 (다대다 관계)
- **[제안]** 일정 변경 이력(누가/언제/무엇을 변경했는지) 조회 — 감사 목적, 3.8 참고

### 3.5 사용자 그룹 관리 **[요청]**
- 그룹 축: **① 역할**(관리자/운영자/일반), **② 조직 그룹**(회사/부서), **③ 업무그룹**(기능/업무 단위)
- 사용자 1명이 조직 그룹·업무그룹에 다중 소속 가능

### 3.6 엑셀 다운로드/업로드 **[요청]**
- **월단위 일정 엑셀 다운로드**: 지정 월의 일정을 표준 서식으로 추출
- **월단위 일정 엑셀 업로드**: 표준 템플릿으로 대량 등록/수정
- **[제안]** 업로드 시 행 단위 유효성 검증 + 오류 리포트(실패 사유 포함) 다운로드 제공, 업로드 전 미리보기(Dry-run) 단계

### 3.7 프로젝트 정보 관리 **[요청]**
- 프로젝트명, 프로젝트 기간(시작~종료), 오픈일자 등 주요 이벤트 관리
- **[제안]** 등록된 오픈일자 등은 자동으로 **마일스톤 이벤트**로 캘린더에 반영, D-day 카운트 표시

### 3.8 감사 로그(활동 이력) **[제안]**
- 100명+ 다부서 인원이 사용하는 환경 특성상, "누가 언제 일정/사용자 정보를 변경했는가"에 대한 추적 필요
- 대상: 일정 등록/수정/삭제, 사용자 권한 변경, 엑셀 업로드, 비밀번호 강제 초기화
- 관리자만 조회 가능, 보관 기간 정책 수립 필요(예: 1년)

## 4. 비기능 요구사항

| 구분 | 내용 |
|---|---|
| 동시 사용자 | 100명+ 동시 접속 대응 (Supabase Postgres 커넥션 풀링 필요 — PgBouncer) |
| 반응형 | PC 웹 + 모바일 웹 반응형 1개 코드베이스 (별도 앱 없음) |
| 보안 | 비밀번호 단방향 해시(bcrypt), 쪽지 내용 암호화(AES-256), HTTPS 강제, 세션 만료 정책 |
| 접근 제어 | 역할 기반 권한 제어(RBAC) — 화면/버튼/API 3중 체크 |
| 가용성 | Vercel + Supabase 관리형 인프라로 자체 인프라 운영 부담 최소화 |
| 데이터 백업 | Supabase 자동 백업(PITR) 설정 **[제안]** |
| 로깅/모니터링 | Vercel Analytics/Logs + Supabase Logs, 감사 로그 별도 테이블 **[제안]** |
