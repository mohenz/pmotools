# 작업 기록 — 회의실 예약 시스템 개발 (2026-08-12)

> 대상 저장소: `projectmgmt`  
> 개발 환경: Next.js 15, React 19, Prisma ORM 7, PostgreSQL 18  
> 로컬 DB: `localhost:55432/mydb`  
> 화면: `http://localhost:3020/meetrooms`

## 1. 작업 목적

`meetroom` 폴더에 있던 설계서, PostgreSQL DDL, React 프로토타입을 분석하고 기존 Project Tool에 실제 동작하는 회의실 예약 기능으로 통합했다.

설계 문서와 초기 자료 사이의 다음 불일치를 먼저 해소했다.

- 비로그인 예약과 회원 로그인 기반 UI/DB의 충돌
- 예약 취소의 상태 보존 설계와 UI 물리 삭제의 충돌
- 정기예약 승인 시 실제 예약 인스턴스가 생성되지 않는 문제
- 사용자·관리자 데이터 모델 불일치
- Supabase 중심 설명과 로컬 PostgreSQL 개발 요구의 차이
- 회의실 삭제 및 감사 추적 정책 부재

## 2. 설계서 보완

`meetroom/회의실예약시스템_설계서.md`를 구현 기준 문서로 개편했다.

주요 결정:

- 모든 사용자는 로그인 필수
- 기존 `users`와 프로젝트 역할 체계 재사용
- 취소는 `CANCELLED` 상태로 논리 처리
- 동일 회의실 시간 충돌은 서버 검증과 DB `EXCLUDE` 제약으로 이중 방어
- 정기예약 승인은 하나의 트랜잭션에서 전체 인스턴스를 생성
- 정기예약 중 하나라도 충돌하면 전체 승인 실패
- 회의실 사용 이력이 없으면 물리 삭제, 이력이 있으면 보관 처리
- 기준 시간대는 `Asia/Seoul`
- 일간·주간·월간 사용현황과 예약 상세 조회 제공
- 활성 프로젝트 사용자를 예약 참석자로 복수 등록

## 3. 로컬 PostgreSQL 구성

시스템 PostgreSQL 18의 기존 역할 정보를 알 수 없어 워크스페이스 내부에 프로젝트 전용 클러스터를 구성했다.

- 데이터 경로: `.local-postgres/data` (Git 제외)
- 포트: `55432`
- 데이터베이스: `mydb`
- 애플리케이션 연결: `.env`의 `DATABASE_URL`
- 시작·중지·상태 확인 스크립트 추가

```powershell
npm run db:local:start
npm run db:local:status
npm run db:local:stop
```

기존 시스템 PostgreSQL 서비스와 포트가 겹치지 않도록 분리했다.

## 5. 구현 기능

### 예약현황

- 일간 회의실별 30분 타임테이블
- 주간 7일 예약 목록
- 월간 날짜별 예약 건수와 예약 목록
- 날짜 및 보기 전환
- 예약 선택 시 상세정보 확인

예약 상세 표시 정보:

- 회의실
- 예약 일시
- 예약자 및 소속
- 사용 목적
- 일반·정기예약 구분
- 참석자 목록

### 단건 예약

- 슬롯 선택 예약
- 운영시간 09:00~19:00
- 30분 단위
- 최대 4시간
- 과거 예약 차단
- DB 동시성 충돌 차단
- 본인 또는 관리자만 시간 변경·취소
- 취소 및 시간 변경 이력 저장

### 참석자

- 프로젝트의 활성 사용자 중 복수 선택
- 비활성·잠금 사용자 제외
- 중복 사용자 제거
- 예약자는 참석자 목록에서 제외
- 예약 조회 응답에 참석자 정보 포함

### 정기예약

- 매일·매주·매월 신청
- 관리자 승인·반려
- 반려 사유 필수
- 승인 시 반복 날짜별 예약과 생성 로그 일괄 생성
- 충돌 발생 시 전체 롤백
- 행 잠금 및 Serializable 트랜잭션 적용

### 회의실 관리

- 관리자 회의실 추가
- 이름·유형·수용인원·위치·장비 관리
- 향후 확정 예약이나 승인 대기 신청이 있으면 삭제 차단
- 사용 이력이 없으면 물리 삭제
- 사용 이력이 있으면 보관 처리
- 보관 회의실 복원
- 모든 관리 작업을 기존 감사 로그에 기록

## 11. 실행 방법

```powershell
npm run db:local:start
npx prisma migrate dev
npx prisma db seed
npm run dev
```

접속 주소:

```text
http://localhost:3020/meetrooms
```

초기 관리자 계정은 기존 seed 정책을 따른다. 운영 또는 공유 환경에서는 seed에 포함된 임시 비밀번호를 환경변수로 분리하고 최초 로그인 시 반드시 변경해야 한다.
