# 집중관리업무 기능 개선 방안

작성일: 2026-09-03
대상: `관리업무`(메뉴 표시명 "집중관리", `ManagementTask` 도메인)

## 0. 요청 원문

> 업무모듈별, 담당자별 집중관리업무 등록
> -> 집중관리 항목별 액션아이템 등록
>    액션아이템 : 번호(시퀀스), 액션아이템구분, 액션아이템명, 우선순위, 중요도, 업무그룹, 담당자, 등록자, 등록일자, 수정일자, 기한, 상태, WBS ID, 비고
>
> 집중관리 평가항목은 집중관리세부항목으로 변경하고 세부항목별 액션아이템을 등록하여 액션아이템의 상태로
> 집중관리 업무를 평가한다.
>
> 상태 : 식별, 진행, 지연, 이슈, 종료
>
> 액션아이템목록조회
> 집중관리업무에 등록된 모든 액션아이템을 조회하는 메뉴이며 PM, PMO만 열람할 수 있다.
> 집중관리업무의 등록은 업무그룹 리더, PMO, 담당자가 등록할 수 있다.

## 1. 현재 구조 (as-is)

- `ManagementTask` 1건 = 집중관리업무 1개. 5개의 **고정 평가항목(축)**을 가진다: 일정관리(prep) · 범위관리(owner) · 자원관리(progress) · 소통관리(issue) · 품질관리(close) (`lib/domain/management-tasks.ts`).
- 항목마다 자유서술(Content) + 수동 입력 퍼센트(Percent)를 담당자가 직접 채워 넣고, `totalScore`(축별 20점 만점 합산)로 `band`(RED/YELLOW/GREEN)를 계산한다.
- `status`는 항목 전체에 1개만 존재(`IDENTIFIED / IN_PROGRESS / ISSUE_TRANSFERRED / RISK_TRANSFERRED / CLOSED`).
- 등록·수정·삭제 전부 `assertManager`(관리자·운영자 role)로만 제한 — 업무그룹 리더·담당자는 등록 불가 (`lib/server/management-tasks.ts`).
- 메뉴 노출은 이미 `hasPmPmoAccess(jobTitle, role)`(jobTitle이 PM/PMO이거나 SUPER_ADMIN)로 제어 중 — PM/PMO 전용 화면이라는 인프라는 이미 존재.
- `Groups.leaderId`(업무그룹 리더) 개념도 이미 존재하고 업무일지 관리 등 다른 기능에서 재사용 중이다.

## 2. 개선안 분석

요구사항의 핵심은 **"평가를 사람이 퍼센트로 수기 입력"** 방식에서 **"실행 단위(액션아이템)를 등록하고 그 상태가 쌓여서 평가가 산출되는"** 방식으로의 전환이다.

### 2.1 제안 데이터 모델

- `ManagementTaskDetailItem`(세부항목): 기존 5개 고정 축(일정/범위/자원/소통/품질)을 그대로 유지하되 개념을 "평가항목"→"세부항목"으로 전환한다. 기존 `content`/`percent` 필드는 액션아이템 집계로 대체되어 폐기한다.
- `ActionItem`(신규): 아래 필드로 구성하고 `ManagementTaskDetailItem`에 FK로 연결한다.
  - `sequenceNo`(번호, 자동 시퀀스), `category`(액션아이템구분), `name`(액션아이템명), `priority`(우선순위), `importance`(중요도), `groupId`(업무그룹), `assigneeId`(담당자), `createdBy`(등록자), `createdAt`(등록일자), `updatedAt`(수정일자), `dueDate`(기한), `status`(상태), `wbsItemId`(WBS ID, nullable), `note`(비고)
- `ActionItemStatus`(신규 enum): `IDENTIFIED(식별) / IN_PROGRESS(진행) / DELAYED(지연) / ISSUE(이슈) / CLOSED(종료)`.
  - 기존 `ManagementTaskStatus`(`ISSUE_TRANSFERRED`/`RISK_TRANSFERRED` 포함)와는 다른 값 구성이다. `지연`이 신규로 생기고, `이슈이관`/`리스크이관`은 `이슈`로 단순화된다.
- `액션아이템구분`(category)은 값 목록이 요청에 명시되지 않았다. 기존 패턴(요구사항 구분·기능분류 등)과 동일하게 `CommonCode`(예: 그룹코드 `action_item_category`)로 관리할 것을 제안한다.

### 2.2 세부항목/전체 항목 평가(band) 산출 규칙 — 결정 필요

요청에 정확한 계산식이 없어 아래 중 하나를 선택해야 한다. **1안을 추천**(현재 신호등 로직의 직관과 가장 가깝고 구현이 단순함).

1. 세부항목 내 액션아이템 중 하나라도 `이슈`가 있으면 RED, 하나라도 `지연`이 있으면(이슈 없을 때) YELLOW, 전부 `종료`면 GREEN, 그 외(식별/진행 혼재)는 YELLOW.
2. 기존처럼 상태별 가중 점수(예: 종료=100%, 진행=50%, 식별=0%, 지연/이슈=0%)를 매겨 세부항목 평균 → `totalScore` → `band`를 그대로 계산.
3. 세부항목 자체에는 점수를 없애고, `band`는 전체 액션아이템 상태 분포만으로 판정(퍼센트/점수 개념 폐기).

### 2.3 권한 모델 변경

| 기능 | 현재 | 개선 후 |
|---|---|---|
| 집중관리업무 등록 | 관리자·운영자만 | 업무그룹 리더 + PMO + 담당자 |
| 집중관리업무 수정 | 관리자·운영자만 | (동일하게 확대할지 확인 필요 — 3.2 참고) |
| 액션아이템 등록 | (신규) | 업무그룹 리더 + PMO + 담당자로 추정 |
| 액션아이템목록조회(전체) | (신규 메뉴) | PM · PMO만 |

`hasPmPmoAccess`를 액션아이템목록조회 메뉴 가드에 그대로 재사용할 수 있다. "업무그룹 리더" 판별은 `Groups.leaderId === session.user.id`로 이미 존재하는 방식을 재사용한다.

## 3. 확인이 필요한 사항 (구현 착수 전 결정 필요)

1. 세부항목→band 산출 규칙은 2.2의 3안 중 어느 것으로 할지, 아니면 다른 계산식이 있는지.
2. "집중관리업무 등록"에 업무그룹 리더/PMO/담당자를 허용하는 것이 **수정·삭제·보관 처리**에도 동일하게 적용되는지, 아니면 등록만이고 수정은 기존처럼 관리자 이상으로 유지하는지.
3. 세부항목(일정관리/범위관리/자원관리/소통관리/품질관리) 5개는 계속 고정인지, 아니면 프로젝트/집중관리항목마다 다르게 구성할 수 있어야 하는지.
4. 액션아이템구분(카테고리)의 실제 값 목록.
5. 기존에 이미 등록된 관리업무 항목들의 축별 Content/Percent 데이터를 어떻게 이관할지 — 폐기, 또는 최초 액션아이템 1건으로 자동 변환.
6. "액션아이템목록조회"는 프로젝트 전체를 가로지르는 단일 목록인지, 아니면 집중관리업무별 하위 목록의 합인지(필터·정렬 요구사항 유무).

## 4. TASK 목록

### A. 설계 확정
- A1. 3장의 확인사항(1~6) 결정
- A2. `ActionItem`/`ManagementTaskDetailItem` ERD 및 상태 전이 규칙 문서화

### B. 데이터/스키마
- B1. `ManagementTaskDetailItem`, `ActionItem` Prisma 모델 추가 + 마이그레이션
- B2. 액션아이템 상태 enum, 액션아이템구분 CommonCode 그룹 추가
- B3. 기존 `ManagementTask`의 axis Content/Percent 필드 → 신규 구조 데이터 이관 스크립트(A1-5 결정에 따름)
- B4. `ManagementTask.status/totalScore/band` 계산 로직을 액션아이템 집계 기반으로 교체

### C. 서버/권한
- C1. `assertManager` 대신 "업무그룹 리더 or PMO or 담당자" 판별 함수 추가(`Groups.leaderId`, `hasPmPmoAccess` 재사용)
- C2. 액션아이템 CRUD API(`/api/v1/management-tasks/[id]/action-items`)
- C3. 액션아이템 전체 목록 조회 API(`/api/v1/action-items`, PM/PMO 전용 가드)
- C4. WBS ID 연결 시 유효성 검증(존재하는 WBS 항목인지)

### D. 화면
- D1. `ManagementTaskDetailScreen`의 5축 표를 "세부항목별 액션아이템 목록 + 등록 폼"으로 교체
- D2. 액션아이템 등록/수정 폼(번호는 자동 시퀀스, 나머지 필드 입력)
- D3. 신규 "액션아이템목록조회" 화면 + 메뉴(PM/PMO 노출 가드)
- D4. 대시보드(`ManagementTaskDashboardScreen`)의 band 집계 로직이 신규 계산식을 그대로 반영하는지 확인

### E. 검증
- E1. `lib/domain/management-tasks.ts` 유닛테스트를 신규 로직으로 교체/추가
- E2. 권한 매트릭스(리더/PMO/담당자/일반사용자) E2E 확인
- E3. 기존 데이터 마이그레이션 결과 검증
