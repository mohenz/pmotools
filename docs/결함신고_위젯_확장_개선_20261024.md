## 1. defect_manage2의 결함신고 흐름 (기준)

1. 테스트 사이트의 위젯 버튼(벌레 아이콘)을 누른다.
2. 팝업을 클릭 시점에 먼저 열고(차단 방지), 현재 보이는 화면을 `html2canvas-pro`로 캡처한다.
3. 페이지 URL, 제목, 화면명, 메뉴명, 브라우저 정보, 테스트 구분을 모아 등록 팝업에 전달한다.
4. 등록 폼이 이 값들을 미리 채워 열린다. 로그인 전이면 로그인 후 같은 등록 화면으로 돌아오고 캡처가 유지된다.
5. Chrome 확장은 같은 흐름을 아이콘 클릭으로 수행한다(탭 캡처 → 새 탭에 등록 화면 → 콘텐츠 스크립트로 데이터 전달).

## 2. pmotools 구현에서 발견한 문제

| # | 문제 | 영향 |
|---|---|---|
| 1 | 공식 위젯(`pmo-defect-widget.js`)에 화면 캡처가 없었다. 캡처 코드는 `test_view.html`에 인라인으로 따로 있었다 | 다른 사이트에 위젯 한 줄을 넣어도 캡처가 안 된다. `test_view.html`에는 버튼이 두 개 떴다 |
| 2 | 등록 폼의 제목·환경 입력칸이 `defaultValue`였다. 메시지는 마운트 뒤에 도착한다 | React가 값을 갱신하지 않아 제목·환경이 비어 있었다. 화면명·메뉴명은 전달 자체가 없었다 |
| 3 | 위젯이 보낸 단계 이름("통합테스트")과 코드 이름("통합")이 정확히 일치해야 매칭됐다 | 테스트 단계가 자동 선택되지 않았다 |
| 4 | 위젯으로 등록해도 등록 경로가 `EXTENSION`으로 저장됐다 | 출처 통계가 틀어진다 |
| 5 | 같은 수집 데이터가 다시 오면 캡처가 중복 첨부됐다(로그인 이동, 개발 모드 이펙트 이중 실행) | 증적 3개 한도를 낭비한다 |
| 6 | 확장이 페이지 안에서 `window.open`을 호출했다. 사용자 동작이 없어 차단될 수 있고, 로그인 이동 시 데이터를 잃었다 | 확장 경로가 불안정하다 |

## 3. 개선 내용

### 3.1 위젯 — `public/defect-widget/pmo-defect-widget.js`

- `html2canvas-pro`로 현재 보이는 화면을 캡처한다. 실패해도 등록은 계속할 수 있다. 캡처 중에는 위젯 버튼을 숨긴다.
- 전달 항목: `pageUrl`, `pageTitle`, `userAgent`, `screenshot`, `title`(`[화면명] 결함 보고`), `menuName`, `screenName`, `testStage`, `caseId`, `source: "WIDGET"`.
- 팝업을 클릭 시점에 먼저 열고, 캡처 뒤 등록 주소로 이동시킨다. 등록 창이 다시 `PMO_DEFECT_READY`를 보내면(로그인 이동 등) 같은 데이터를 다시 보내고, 창이 닫히면 리스너를 정리한다.
- 설정: script 속성 `data-pmotools-url`, `data-test-stage`, `data-case-id`, `data-menu-name`, `data-screen-name`, `data-button="none"`. head 메타 `pmo:menu-name`, `pmo:screen-name`.
- 자체 버튼을 쓰는 사이트는 `window.PmoDefectWidget.open()`을 호출한다.

### 3.2 등록 폼 — `features/mp/defects/DefectForm.tsx`

- 제목·메뉴명·환경을 상태값으로 바꿔 수집값이 실제로 채워진다. 사용자가 이미 입력한 값은 덮어쓰지 않는다.
- 단계 이름은 코드·이름 일치, 포함 관계 순으로 매칭한다.
- 캡처는 `capture.*` 한 장만 유지한다.
- 등록 경로(`sourceType`)는 수집 데이터의 `source`를 쓴다.
- 메시지 검증
  - 위젯: 대상 도메인에 등록된 출처이고 `event.source === window.opener`일 때만 받는다.
  - 확장: 등록 창 안에서 주입된 메시지만 받고, 수집한 페이지 주소의 출처가 대상 도메인에 등록돼 있어야 한다(설계서 6.2 유지). 등록되지 않았으면 오류 메시지를 보여 준다.
- 확장용으로 폼이 자기 창에 `PMO_DEFECT_READY`·`PMO_DEFECT_CLOSE`를 보낸다.

### 3.3 확장 프로그램 — `defect_extension/`

- 아이콘 클릭 시 탭을 캡처하고 페이지에서 화면명·메뉴명을 읽는다.
- `chrome.windows.create`로 등록 팝업 창을 직접 만든다(`window.open` 차단 회피).
- 그 창에 브리지 스크립트를 주입한다. 브리지는 READY에 DATA로 응답하고, CLOSE를 받으면 확장에 창 닫기를 요청한다.
- 로그인 이동 등으로 새 문서를 불러올 때마다 브리지를 다시 주입한다. 수집 데이터는 `chrome.storage.session`에 창(탭) 단위로 보관하고 창이 닫히면 지운다.
- `manifest.json`: 버전 1.1.0, `optional_host_permissions` 추가. 옵션 페이지는 저장 시 PMOTOOLS 주소에 대한 접근 권한을 요청한다.

### 3.4 테스트 사이트 — `public/test_view/test_view.html`

- 인라인 캡처·등록 코드와 별도 버튼을 제거했다.
- 헤더의 등록 버튼은 `PmoDefectWidget.open()`을 호출하고, 위젯 스크립트에 `data-test-stage="통합"`을 지정했다. 위젯 버튼은 하나만 남는다.

## 4. 메시지 규격 (갱신)

| 메시지 | 방향 | 내용 |
|---|---|---|
| `PMO_DEFECT_READY` | 등록 화면 → 위젯(opener) 또는 확장 브리지(자기 창) | 등록 화면 준비 완료 |
| `PMO_DEFECT_DATA` | 위젯 또는 확장 브리지 → 등록 화면 | `payload`: `pageUrl`, `pageTitle`, `userAgent`, `screenshot`, `title`, `menuName`, `screenName`, `testStage?`, `caseId?`, `source` |
| `PMO_DEFECT_CLOSE` | 등록 화면 → 위젯 또는 확장 브리지 | 등록·취소 후 창 닫기 |

## 6. 남은 확인 사항

1. `chrome://extensions`에서 확장을 새로고침하고 옵션에서 PMOTOOLS 주소를 다시 저장한다(권한 허용 창이 한 번 뜬다).
2. cinetube(`localhost:8080`) 등 대상 사이트에서 위젯·확장으로 등록해 제목, 화면명, 캡처, 테스트 단계가 채워지는지 확인한다.
3. 로그아웃 상태에서 신고해 로그인 후에도 캡처가 유지되는지 확인한다.
4. 설계서 3.1·6.2에 새 필드(`title`, `menuName`, `screenName`, `source`)와 확장의 팝업 창 주입 방식을 반영한다(아직 반영하지 않음).

## 7. 추가 수정 — 캡처가 등록 화면에 보이지 않던 문제 (2026-10-24)

| 원인 | 조치 |
|---|---|
| 증적 선택기가 파일명·크기만 보여 주고 이미지 미리보기가 없었다 | `DefectForm`에 첨부 이미지 미리보기 추가(단위테스트 선택기는 규칙 1에 따라 수정하지 않음) |
| 개선 중 같은 출처(PMOTOOLS 자신, `/test_view` 포함)를 허용하던 예외를 빼서, 대상 도메인에 등록되지 않은 출처의 위젯 메시지가 **조용히 버려졌다**. 이때 캡처·제목·화면 정보가 모두 비었다 | PMOTOOLS 자신의 출처를 다시 신뢰하고, 거절되면 화면에 이유(대상 도메인 등록 안내)를 표시 |
| 캡처가 오지 않았거나 형식·크기 때문에 첨부되지 못해도 안내가 없었다 | 사유별 안내 문구 추가 |

검증: 등록 폼에 `PMO_DEFECT_DATA`(캡처 포함)를 전달하면 증적 아래에 600×300 미리보기가 렌더링되고 제목·메뉴명이 채워지는 것을 브라우저에서 확인했다.
