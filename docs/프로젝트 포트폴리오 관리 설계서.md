## 3. 화면 설계

**경로:** `/pmo-daily/portfolio` · 메뉴: **PMO Daily 하위 탭 "프로젝트 포트폴리오"**(2026-10-20 사용자 지시) — `[대시보드] [일자별 목록] [신규 작성] [프로젝트 포트폴리오] [일정관리]`. 기존 "통합 현황"(`/portfolio`, 개인 대시보드)과 이름·경로·코드를 공유하지 않는다. 고정 경로 `portfolio`는 Next.js 규칙상 동적 경로 `/pmo-daily/[date]`보다 우선한다(`dashboard`·`new`와 같음).

## 4. 지표 계산 규칙

모든 Task 지표는 **보관되지 않은 Leaf WBS**(하위 항목이 없는 행) 기준이며, 기존 WBS 통계 화면과 같은 값을 낸다.

| 지표 | 정의 | 출처 |
|------|------|------|
| 전체 Task | Leaf WBS 수 | `getWbsStats().itemCount` |
| 완료 Task | 실적 진척 100%인 Leaf (실적종료일 입력 또는 역할 트랙 평균 100%) | Leaf 중 `actualProgress ≥ 1` (기존 `countStatsOf`와 같은 기준) |
| 미완료 Task | 전체 − 완료 | 계산 |
| 지연 Task | `isWbsItemDelayed` 해당 Leaf | `getWbsStats().delayedCount` |
| 공정율 | **실적 공정율** — Leaf 가중(가중치 → 없으면 영업일수) 평균 실적 % | `getWbsStats().overall.actual` (9장 D2) |
| 예상공정율 | **오늘 기준으로 계획상 도달해 있어야 할 공정율** — Leaf별 계획 진척(계획시작~계획종료 기간 중 오늘까지 경과 비율, 시작 전 0%·종료 후 100%)의 가중 평균. 기존 WBS 화면의 "계획 공정율(목표 today)"과 같은 값 | `overall.planned` |
| 공정율 차이 | 공정율 − 예상공정율 (%p). 음수면 계획 대비 뒤처짐 | 계산 |
| 지연율 | 지연 Task ÷ 계획종료일이 오늘 이전인 Leaf 수 | `getWbsStats().delayRate` |
| 대표 행·상단 합계 | 건수는 단순 합. 공정율은 하위 프로젝트 Leaf 전체를 다시 가중 평균(프로젝트 평균의 평균 아님). 지연율은 지연 합 ÷ 도래 합 | 신규 순수 함수 `aggregatePortfolio()` |

- 공정율 합산을 "프로젝트별 공정율의 단순 평균"으로 하면 Task 10건짜리와 1,000건짜리가 같은 비중이 되어 왜곡된다. 가중치 합 기준으로 재계산한다.

## 5. 프로젝트 상태 (예정·진행·완료) — 2026-10-20 확정(D1)

상태는 **공정율(실적 공정율, 4장)** 로 자동 산정한다. DB 변경 없음.

| 상태 | 조건 |
|------|------|
| 예정 | 공정율 < 1% (WBS Leaf가 없는 프로젝트 포함) |
| 진행 | 1% ≤ 공정율 < 100% |
| 완료 | 공정율 ≥ 100% (전 Leaf 실적 100%) |

- 판정은 반올림 전 원값(0~1)으로 한다. 완료는 소수 오차를 피하기 위해 `완료 Task = 전체 Task`(> 0)로 판정한다.
- 대표 행의 상태는 하위 합산 공정율(4장 가중 재계산)로 같은 규칙을 적용한다.
- 보조 경고(판정에는 영향 없음): 종료일이 지났는데 완료가 아니면 상태 칸에 "종료일 경과" 경고, 시작일이 지났는데 예정이면 "착수 지연" 경고.

## 6. 기능 설계

| 구분 | 내용 |
|------|------|
| 서버 | `lib/server/project-portfolio.ts` — `listPortfolioProjects()`: 대표 프로젝트 계층 전체로 범위 결정(6장 권한) → 프로젝트별 `getWbsStats()` 병렬 호출(30초 캐시 재사용) → 행 조립 |
| 도메인(순수 함수) | `lib/domain/project-portfolio.ts` — `projectStatusOf(actual, completedCount, totalCount)`(5장 규칙), `scheduleWarningOf(start, end, today, status)`, `aggregatePortfolio(rows)`(가중 재계산), `completedCountOf(leaves)` + Vitest |
| 기존 함수 보강 | **하지 않음(구현 시 변경 2026-10-20)** — `loadWbsStats`를 고치지 않고 `listWbsItems`(보관 제외·메모리 캐시)에서 같은 Leaf·가중치·지연 규칙으로 직접 계산(`metricsOfLeaves`). 기존 WBS 화면 회귀 위험 0. 계층 탐색 함수 `topAncestorOf`·`descendantsOf`만 export |
| API | `GET /api/v1/pmo-daily/portfolio` (화면은 서버 컴포넌트로 직접 호출, API는 새로고침용) |
| 화면 | `app/pmo-daily/portfolio/page.tsx`, `screens/ProjectPortfolioScreen.tsx` |
| 메뉴 | `components/AppNavigation.tsx`의 PMO Daily 하위 탭 배열(`"/pmo-daily": [...]`)에 `{href:"/pmo-daily/portfolio",label:"프로젝트 포트폴리오"}` 1개 추가. 신규 최상위 메뉴 키는 만들지 않는다. 기존 `portfolio` 항목·`/settings/portfolio-panels`·`portfolio_panel_preferences`는 변경 없음 |
| 기존과의 경계 | 신규 코드는 `portfolio-panels`·`PortfolioScreen`을 import하지 않는다. 공유하는 것은 WBS 계산 함수(`getWbsStats`, `isWbsItemDelayed`)와 프로젝트 범위 규칙(`listMpProjects`)뿐 — 같은 Task가 화면마다 다른 수치로 보이지 않게 하기 위함 |
| 권한 | 조회 전용. **PMO Daily와 같이 PM/PMO만 접근**(`requirePmPmoContext`). 표시 범위 = **로그인 프로젝트가 속한 대표 프로젝트의 하위 프로젝트 전체**(배정 여부와 무관, 2026-10-20 확정 D3). `listMpProjects`의 배정 필터는 쓰지 않고 계층 탐색 함수(`topAncestorOf`·`descendantsOf`, 현재 `lib/server/mp/context.ts` 내부 함수)를 export해 재사용 — 동작 변경 없음 |
| 성능 | 프로젝트 N개 × `getWbsStats` 1회(캐시). 프로젝트 20개 기준 캐시 미스 시에도 병렬 처리. 50개 초과 시 일 스냅샷 방식 검토 |
| DB 변경 | **없음** (D1-A 채택 시) |
| 감사로그 | 조회 화면이라 기록 없음 |
