## 1. 프로젝트 개요 및 추진 배경

### 1.1 개요
본 문서는 `PMOTOOLS` 플랫폼 내 **산출물 관리 시스템(Deliverables Management System)** 구축을 위한 **최종 단일 기준 작업계획서**이다.
프로젝트 수행 과정에서 생산되는 각종 산출물의 등록, 1~5차 다차수 검수 파이프라인, SharePoint 원본 링크 연계, 엑셀 대량 관리, 그리고 공공·대기업 SI 감리 기준을 충족하는 **불변 감사 증적(Audit Evidence Snapshot)** 체계를 무결하게 구현·배포하는 것을 목적으로 한다.

### 1.2 추진 목적 및 기대 효과
1. **산출물 생애주기 전산화**: 등록 ➔ 1~5차 다차수 검수 ➔ 보완요청/부적격 재검수 ➔ 최종 적격 확정 전 과정을 시스템화.
2. **감사 리스크 원천 차단**: 검수 완료(적격·보완요청·부적격) 시점마다 문서 URL, 파일명, SharePoint 버전/수정일시를 불변 이력으로 동결 보존하여 사후 임의 수정에 따른 감리 지적을 예방.
3. **진척 지연 가시화**: 산출물별 계획제출일(`plannedSubmitDate`) 및 실제제출일(`submittedAt`)을 추적하여 프로젝트별 산출물 기준 공정 진척율(SPI) 산출 기반 마련.
4. **대량 처리 생산성 확보**: WBS 및 요구사항 관리에서 검증된 스테이징 엔진을 재사용하여 수백 건의 산출물을 엑셀로 일괄 등록/수정하고 화면에서 즉시 정정 반영.

### 1.3 검토 원천 문서 및 추적성 (Traceability)
본 계획서는 아래 핵심 선행 문서를 전수 교차 대조하여 작성되었다:
- **기준 설계서**: `docs/프로젝트 산출물 관리 기능 설계서.md` @ `be15077` (P5·P6 확정판)
- **PMO 검토서**: `docs/산출물관리_설계서_PMO검토.md` (2026-10-13 검토, A1~A3, S1~S5, P1~P4 반영)
- **PMO 정밀 검토서**: `docs/산출물관리_시스템개발작업계획서_PMO검토_20261019.md` (2026-10-19 검토, K1~K4, D1~D6, O1~O5, G1~G5 전수 수용)

## 7. C-Level 결정 사항 및 미결정 시 영향 (Consequence of Inaction - G2 정제)

본 작업계획서에 제시된 **검수 시점별 감사 증적 스냅샷(A1/D1)**, **이력 연쇄 삭제 방지 FK Restrict(P5)**, **상태 전이 롤백 FSM(S1)**, 그리고 **수기 무손실 마이그레이션** 체계를 통제하지 않은 채 기능 개발을 서두를 경우 다음과 같은 치명적 리스크가 발생합니다:

1. **정기 감리 시 검수 증적 불인정 위험 (Audit Failure Exposure)**:  
   적격 판정 이후 외부 SharePoint 문서가 임의 변경되어도 시스템이 감지하지 못하므로, 정기 감리 시 "검수 시점의 문서 내용 입증 불가"로 감사 지적이 발생합니다. 이 경우 DB 스키마 재설계와 기존 이력 소급 불능에 따른 **추가 개발 및 감리 대응 공수(최소 2~3주 M/D)가 추가 소요**됩니다.
2. **연쇄 삭제에 의한 법적 증적 소실 (Compliance Risk)**:  
   P5(`onDelete: Restrict`)를 미반영할 경우 프로젝트나 산출물 물리 삭제 1건으로 1~5차 검수 승인 이력이 연쇄 영구 소실되어, 그룹사 내부통제 감사 기준을 위반하게 됩니다.
3. **상태 불일치로 인한 워크플로우 교착 (Stall Risk)**:  
   상위 차수 정정 시 하위 차수가 롤백되지 않으면 결재선 교착이 발생하여, 매번 DB 직접 수동 업데이트가 수반되는 불필요한 운영 공수(OPEX)가 지속 발생합니다.
4. **백오피스 DB 스키마 훼손 위험**:  
   Prisma 자동 diff 마이그레이션을 사용할 경우 백오피스(`pmotools_admin`) 테이블 DROP 위험이 상존하므로, 수기 무손실 마이그레이션 원칙을 철저히 고수해야 안정적인 서비스 가동을 보장할 수 있습니다.
