# 작업기록: pmotools_admin 고유 기능 pmotools 메인 앱 통합 (Consolidation)

- **작성일자**: 2026-10-12
- **작성자**: Rick Deckard (Strategic PMO Agent)
- **목적**: 별도 운영되던 `pmotools_admin`(백오피스) 웹 애플리케이션의 고유 기능(플랫폼 프로젝트 관리, 전역 공통코드 관리)을 메인 `pmotools` 애플리케이션의 `SUPER_ADMIN` 전용 관리 영역으로 흡수 통합하여 이중 배포 비용 및 기술 부채 제거.

---

## 1. 배경 및 의사결정 사유
1. **문제점**:
   - `pmotools_admin`은 플랫폼 확장을 위해 신축되었으나, 일반 프로젝트 관리 기능(사용자/그룹/회의실/주차 등)의 90% 이상이 메인 앱과 중복되어 있었음.
   - 프로젝트 생성, 전역 코드 등 고유 기능은 이용 빈도가 극히 낮아(연 1~2회) 별도 웹 프로세스/포트를 상시 유지하는 데 따른 운영 비용(OPEX) 및 코드 불일치(Code Drift) 리스크가 컸음.
2. **해결 방안 (Option A 통합)**:
   - 두 시스템이 이미 동일한 PostgreSQL 인스턴스를 공유하고 있으므로, `pmotools_admin`의 고유 기능만을 추출하여 메인 `pmotools`의 `SUPER_ADMIN` 권한 전용 메뉴로 일원화 이관.

---

## 2. 통합 이관된 주요 기능

### ① 플랫폼 프로젝트 관리 (`/settings/projects`, `/settings/projects/[id]`)
- **신규 프로젝트 생성**: 프로젝트 코드(`code`), 명칭(`name`), 상위 프로젝트(`parentId`) 등록.
- **프로젝트 상하위 계층 트리 관리**: 순환 참조 방지 알고리즘이 적용된 상하위 프로젝트 연결.
- **프로젝트 노출 우선순위 조정 (`reorder`)**: 위/아래 이동 버튼을 통해 프로젝트 전환 드롭다운 및 WBS2 대상 프로젝트 선택 순서 제어.
- **로그인 화면 노출 여부 (`visibility`)**: 미공개/준비 중인 프로젝트의 로그인 화면 숨김 제어.
- **다중 프로젝트 번호 체계 통제 (`numberingBase`)**: 다중 프로젝트 간 이슈(`ISU-`), 요구사항(`REQ-`) 등의 식별자 충돌 방지를 위한 10만 단위 자동 발번 블록 조회.
- **프로젝트 멤버 배정/해제 (`ProjectMembersPanel`)**: 전사 사용자 풀에서 특정 프로젝트로의 인원 할당 및 해제.
- **프로젝트 상세 정보 관리**: 관리자 권한으로 임의 프로젝트의 기간, 오픈 방식, 발주/수행 조직, 등급 수정.

### ② 플랫폼 전역 공통코드 관리 (`/settings/global-common-codes`)
- 특정 프로젝트에 귀속되지 않는 전사 표준 코드(회사정보, 직무 등 `projectId IS NULL`) 및 코드 그룹 생성·수정·활성화 제어.

## 4. 보안 및 접근 제어 검증 (SoD)
- 모든 신규 관리자 페이지(`settings/projects`, `settings/global-common-codes`)는 `requireSuperAdminContext()` 가드를 통해 플랫폼 전역 슈퍼관리자(`globalRole === "SUPER_ADMIN"`)만 접근할 수 있도록 차단됨.
- 일반 사용자(`MEMBER`), 프로젝트 운영자(`OPERATOR`), 단일 프로젝트 관리자(`ADMIN`)가 직접 URL로 접근 시 즉시 메인 페이지(`/`)로 리다이렉트되어 권한 분리(SoD) 보장.

---

## 5. 기대 효과
1. **운영 인프라 단순화**: 2개로 분리 운영되던 웹 서버 포트 및 배포 파이프라인을 1개로 단일화하여 유지보수 비용(TCO) 대폭 절감.
2. **세션/도메인 크로스 이슈 해결**: 포트 간 쿠키 격리, 로그아웃 시 localhost 리졸브 오류 등의 네트워크 장애 요인 원천 제거.
3. **사용자 경험 극대화**: 최고관리자가 프로젝트 생성이나 멤버 배정을 위해 다른 포트로 이동하지 않고 단일 환경에서 즉시 통제 가능.
