## 3. 2026-11-01

### 3.1 WBS 분석 메뉴

PMO Daily 아래를 두 묶음으로 나눴습니다.

- **PMO Daily**: 대시보드, 프로젝트현황, 일자별 목록, 신규 작성
- **WBS 분석**: 대시보드, 간트 차트, 주간 통계, 업무그룹별 통계, 지연 이력, 생산성, 인당부하, 데이터 관리, WBS 항목 등록

원본(`/wbs/…`)과 다중 프로젝트(`/mp-wbs/…`)가 같은 화면을 씁니다. 새 경로는 `analysis`, `productivity`, `workload`입니다.

| 화면 | 내용 |
| --- | --- |
| 대시보드 | 처리율, 기한 경과 미완료, 담당자 미지정, 편중 월, 월별 인당 부하, 주의 담당자와 업무그룹 |
| 생산성 | 기준일까지 기한이 도래한 Task 대비 완료 비율. 업무그룹별·담당자별, 평가 상·중·하 |
| 인당부하 | 계획 일정만으로 본 월별 배치량. 업무그룹별·담당자별 월 부하, 과다·여유·공백 월 |

업무그룹은 설정 > 프로젝트 관리 > 전체 프로젝트 목록 순서로 묶어 정렬합니다. WBS 주간 통계의 업무그룹 정렬도 같은 기준으로 바꿨습니다.

### 3.2 계산 기준 (`lib/domain/wbs-workload.ts`)

- **인당 부하**: 한 사람이 한 달 동안 평균 몇 건을 동시에 진행하는지입니다. 그 달에 걸친 계획 Task의 영업일 합 ÷ 그 달 영업일. 주말만 제외하고 공휴일은 반영하지 않습니다.
- **과다·여유**: 그 달 배치 담당자 중앙값의 1.5배 이상이 과다, 0.5배 이하가 여유입니다.
- **균형**: 담당자 간 변동계수 0.5 이하 균형, 1.0 이하 보통, 초과 편중.
- **처리율**: 계획 종료일이 기준일(오늘)까지 도래한 Task 중 완료 비율. 영업일 가중 처리율, 정시 완료율, 기한 경과 미완료, 부하당 월 처리도 함께 봅니다.
- **표본 등급**: 기한이 도래한 Task 수 기준으로 A(10건 이상), B(5~9건), C(1~4건), D(없음).
- **평가**: 처리율 95% 이상 상, 80% 이상 중, 미만 하. 표본 C·D는 "평가 불가"입니다.
- 평가는 참고값입니다. 보수나 순위 용도로 쓰지 않습니다.

실데이터(읽기 전용)로 확인한 결과: 분석 기간 14개월, 대상 Task 2,752건, 담당자 미지정 116건, 전체 처리율 95.8%, 기한 경과 미완료 50건.

한계: 완료 Task의 실적 종료일이 계획과 거의 같게 기록되어 정시 완료율이 높게 나옵니다. 공수 데이터가 없어 모든 Task를 같은 무게로 셉니다.

### 3.3 상세 화면

- 생산성과 인당부하 표에서 업무그룹이나 담당자 이름을 누르면 상세 화면이 열립니다 (`?group=…`, `?owner=…`).
- **생산성 상세**: 평가·처리율·영업일 가중·정시 완료율·기한 경과 미완료·부하당 월 처리 KPI, 월별 Task 수량 그래프(계획 종료월 기준, 2026-07~2027-08 고정, 완료·기한 경과 미완료·진행/예정 + 옅은 추이선), WBS Task 현황 표.
- **인당부하 상세**: 월별 부하 막대(과다·적정·여유 색), 비교값 선(그룹은 전체 인당 부하, 담당자는 배치 담당자 중앙값), 월별 표, WBS Task 현황 표.
- 제목 옆 ⓘ 툴팁(`components/InfoTip.tsx`)으로 "인당 부하란?"을 설명합니다.
- KPI 카드는 대시보드·상세·인당부하에서 한 줄로 배치합니다.

### 3.4 캘린더 국경일·공휴일

- 캘린더의 월간·주간·일간·년간·목록에 `holidays` 테이블의 국경일·공휴일을 빨간 날짜와 이름으로 표시합니다. 일정이 아니므로 수정·삭제 대상이 아닙니다.
- `holidays` 테이블은 WBS 영업일·지연일 계산에도 쓰입니다. 평일 공휴일이 들어가면 해당 기간의 영업일과 지연일이 달라질 수 있습니다.

- 로컬 DB(`localhost:55432`)에는 2026~2027년 46건을 반영했습니다 (노동절·제헌절과 대체공휴일 포함).
- 데이터는 [holidays-2026-2027.md](holidays-2026-2027.md), 다른 PC에서 DB를 만들고 넣는 절차는 [holidays-setup-guide.md](holidays-setup-guide.md)에 있습니다.

## 4. 다른 PC에서 확인하는 방법

1. 저장소를 받고 DB를 준비합니다 (`holidays-setup-guide.md`의 1~2장).
2. 공휴일을 넣습니다.

   ```bash
   npx tsx scripts/sync-holidays.ts --file docs/holidays-2026-2027.md           # 미리보기
   npx tsx scripts/sync-holidays.ts --file docs/holidays-2026-2027.md --apply   # 반영
   ```

3. 개발 서버를 켜고(`npm run local`, `http://localhost:3020`) 아래를 확인합니다.
   - `/mp-wbs/analysis`: KPI 6개가 한 줄로 보이는지
   - `/mp-wbs/productivity`: 업무그룹·담당자 이름 클릭 → 상세 화면, 월별 Task 수량 그래프
   - `/mp-wbs/workload`: 업무그룹·담당자 이름 클릭 → 월별 부하 그래프, 제목 옆 ⓘ 툴팁
   - `/calendar`: 2026-09-25(추석) 같은 날짜가 빨간색 날짜와 이름으로 보이는지
4. 검증 명령: `npx tsc --noEmit`, `npx vitest run lib/domain/wbs-workload.test.ts lib/domain/public-holidays.test.ts`

참고: 생산성 분석 문서 3종(`docs/생산성/`)은 원래 PC에만 있고 저장소에는 올리지 않았습니다. 다른 PC에서 필요하면 따로 옮기거나 저장소에 올릴지 알려 주세요.

## 6. 남은 일과 주의

- 사내 서버와 Vercel 등 **다른 DB에는 공휴일이 아직 없습니다.** 해당 환경의 `DATABASE_URL`로 위 명령을 미리보기 → 반영 순서로 실행하세요. 평일 공휴일이 WBS 영업일에 반영되므로 미리보기를 먼저 확인해야 합니다. 2028년 이후는 API로 연도를 추가합니다.
- 레지스트리상 GitHub `main` 푸시는 Vercel 자동 배포를 시작시킵니다. 이번 푸시의 배포 결과는 확인하지 않았습니다.
- 기존 실패 테스트 2건(`wbs-pagination-ui`)은 이번 작업 전부터 실패하던 것입니다. 메뉴 구조에 맞게 갱신이 필요합니다.
- 업무그룹별 통계(다중 프로젝트)는 아직 프로젝트 코드 순으로 정렬됩니다. 프로젝트 순서 정렬은 주간 통계와 WBS 분석에만 적용했습니다.
- 공휴일 관리 화면이 필요한지, 필요하면 전사 공통만 둘지 프로젝트별도 둘지 정해야 합니다.
- 공공데이터 인증키는 `.env.local`의 `DATA_GO_KR_SERVICE_KEY`에 있고 git에는 올라가지 않습니다. 다른 PC에서 API를 쓰려면 그 PC의 `.env.local`에 직접 넣으세요. md 파일에서 넣는 방법은 키가 필요 없습니다.
